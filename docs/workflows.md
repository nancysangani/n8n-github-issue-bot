# 🔄 Workflow Documentation

This document explains the complete **AI GitHub Issue Triage workflow** built using **n8n, Groq LLM, and GitHub REST API**.

The workflow automatically analyzes GitHub issues, generates AI-based classifications, applies intelligent labels, creates missing repository labels, generates AI analysis comments, and performs confidence-based automation.

---

# 1. GitHub Trigger Node

## Purpose

Receives GitHub issue events through webhook integration.

Triggered when:

```
issues.opened
```

The webhook payload contains:

```json
{
  "title":"",
  "body":"",
  "issue_number":"",
  "repository":""
}
```

---

# 2. Edit Fields Node

## Purpose

Extracts required information from the GitHub webhook payload.

Extracted fields:

```json
{
  "title":"",
  "description":"",
  "issue_number":"",
  "owner":"",
  "repository":""
}
```

This simplifies data handling for downstream workflow nodes.

---

# 3. Groq AI Classification

## Purpose

Uses Groq LLM to analyze the GitHub issue and generate structured AI-based classification.

## Input

```
Issue Title
Issue Description
```

## Output

```json
{
  "category": "Bug",
  "priority": "High",
  "severity": "Critical",
  "confidence": 92,
  "labels": [
    "bug",
    "backend",
    "api"
  ],
  "affectedComponent": "Authentication Service",
  "estimatedComplexity": "Medium",
  "suggestedTeam": "Backend",
  "comment": "Investigate backend authentication failure.",
  "reasoning": "The issue affects a critical user flow."
}
```

Supported categories:

- Bug
- Feature
- Technical
- Documentation
- UI/UX
- Performance
- Security
- Question

---

# 4. Code Parser Node

## Purpose

Parses the JSON response generated by Groq LLM.

The node extracts:

- Category
- Priority
- Severity
- Confidence score
- Labels
- Affected component
- Estimated complexity
- Suggested team
- Comment
- Reasoning

The extracted information is used by the automation pipeline.

---

# 5. Intelligent Label Management

The workflow dynamically manages GitHub labels.

## Process

1. AI generates multiple labels from the allowed label list.
2. HTTP Request node fetches existing repository labels.
3. Code Parser compares AI-generated labels with existing labels.
4. Missing labels are identified.
5. Split Out node prepares missing label metadata.
6. HTTP Request node creates missing labels automatically.
7. Custom colors and descriptions are assigned.
8. Multiple labels are applied to the GitHub issue.

## Supported Features

- Multiple AI-generated labels
- Automatic missing label creation
- Custom label colors
- Custom label descriptions
- Duplicate label prevention

---

# 6. Confidence-Based Automation

After AI analysis, the workflow evaluates the confidence score returned by the LLM.

## Confidence Rules

| Confidence | Action |
|------------|--------|
| ≥90% | Labels + AI comment + Automatic assignment |
| 70-89% | Labels + AI comment + Manual assignment |
| <70% | Add `needs-review` label + Human review |

---

# Confidence Router Node

The Confidence Router controls the next workflow action.

### High Confidence (≥90%)

```
Confidence Score
        |
        ↓
AI Comment
        |
        ↓
Automatic Assignment
```

The issue is automatically assigned to the repository owner.

---

### Medium Confidence (70-89%)

```
Confidence Score
        |
        ↓
AI Comment
        |
        ↓
Manual Review
```

The issue receives labels and comments but is not automatically assigned.

---

### Low Confidence (<70%)

```
Confidence Score
        |
        ↓
Add needs-review Label
        |
        ↓
Human Review Required
```

The workflow prevents automatic assignment for uncertain classifications.

# 8. Automatic Assignment

## Purpose

Assigns issues automatically based on AI confidence.

## Assignment Logic

### High Confidence (≥90%)

Automatically assigns the issue to:

```
Repository Owner
        ↓
GitHub Assignee
```

Expression:

```javascript
{{$node["Edit Fields"].json.owner}}
```

---

### Medium Confidence (70-89%)

- Labels applied
- AI comment generated
- Manual assignment required

---

### Low Confidence (<70%)

- `needs-review` label added
- Human review required
- No automatic assignment

# Workflow Summary

The workflow provides an end-to-end AI-powered GitHub issue management system by:

- Receiving issue events through GitHub Webhooks
- Analyzing issues using Groq LLM
- Generating category, priority, severity, confidence score, and labels
- Creating missing repository labels automatically
- Applying labels with custom metadata
- Posting structured AI analysis comments
- Performing confidence-based automation
- Automatically assigning high-confidence issues
- Routing uncertain issues for human review

This modular architecture enables scalable, event-driven AI-assisted issue triage with minimal manual intervention.
